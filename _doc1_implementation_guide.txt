1. Deep analysis of the problem
1.1 What is actually being asked
1.2 Where the points are won (and lost)
Only two things are scored automatically: classification quality and detection lead time. The organizers say lead time is where teams differentiate, so the radar (Section 9) gets the most engineering care.
The detector must be causal. At time t it may only use records with timestamp ≤ t. Using future data would inflate lead time and is meaningless operationally. Section 9 builds a replay-style detector and Section 17 has a test that proves causality.
‘Small in absolute volume but rising sharply at one store’ means each store must be compared with its own history. A national top-N list only fires after the damage is done.
Raw counts mislead because stores differ hugely in size. Normalize by exposure. No visit or transaction counts are promised, so use a documented proxy: the store’s own total feedback volume.
Safety, allergen, hygiene and staff-misconduct mentions are high-severity by policy regardless of volume. That must live in a rule layer that no model score and no deduplication step can suppress.
Those rules fight the precision statement: a keyword rule fires on harmless text such as ‘no cockroach, very clean’. Resolution: two escalation tiers that are measured separately (Section 13.3).
Feedback is unverified: one angry review is not a systemic issue. Trend alerts need a minimum number of unique reports. Policy alerts are labelled ‘needs human review, unverified’.
Labels are hidden, so you cannot train or tune on them. The first thing to check is whether the package includes any labeled training sample. Your entire classification strategy depends on the answer (Section 7.3).

2. Product definition, scope and architecture
2.1 Final definition
StoreSignal AI is a multilingual retail early-warning system. It fuses customer and staff feedback from four channels, detects emerging and high-risk incidents, explains every alert with source evidence, routes it to the owning function, tracks follow-through, and writes a weekly one-page brief per region.
2.2 Scope: build the chain first
P0 (foundation): ingestion, normalization, classifier, policy guardrail, early-warning radar, evaluation.
P1 (high value): deduplication and fusion, evidence-backed alerts, routing, regional brief, Streamlit UI.
P2 (stretch): root-cause graph, resolution tracker, feedback loop, forecasting, action-impact simulator.
Rule: do not start P2 until the chain from raw files to a regional brief works on your data. A reliable single flow beats many disconnected features.

2.5 Design principles
Raw data is immutable. Every derived file can be rebuilt with one command.
Three separate mechanisms: classifier (statistics), policy (rules), radar (trend). None can switch off another.
Everything is explainable: every alert stores the rule or the numbers that triggered it and the IDs of its source records.
Simple first: logistic regression and a Poisson test before anything fancy.
Honest labelling: synthetic, estimated and measured values are visibly different.
A human stays in the loop for safety, compliance and staff-conduct decisions.

# src/storesignal/ingest.py
import json
import pandas as pd
from pathlib import Path
from .adapters import CHANNELS, STORE_MASTER
from .config import cfg, ROOT

def load_channel(name, spec, raw):
    df = pd.read_csv(raw / spec['file'], dtype=str, encoding='utf-8', encoding_errors='replace')
    df = df.rename(columns=spec['map'])
    for c in ['source_id', 'ts', 'store_id', 'text_raw', 'rating']:
        if c not in df:
            df[c] = None
    df['channel'] = name
    df['record_id'] = name + '-' + df['source_id'].astype(str)
    df['ts'] = pd.to_datetime(df['ts'], errors='coerce')        # if values carry offsets add utc=True
    if df['ts'].dt.tz is None:
        df['ts'] = df['ts'].dt.tz_localize(cfg['timezone'], nonexistent='shift_forward', ambiguous='NaT').dt.tz_convert('UTC')
    df['rating'] = pd.to_numeric(df['rating'], errors='coerce')
    return df[['record_id', 'channel', 'ts', 'store_id', 'text_raw', 'rating']]

def run():
    raw = ROOT / cfg['paths']['raw']
    df = pd.concat([load_channel(n, s, raw) for n, s in CHANNELS.items()], ignore_index=True)
    stores = pd.read_csv(raw / STORE_MASTER['file'], dtype=str).rename(columns=STORE_MASTER['map'])
    df = df.merge(stores[['store_id', 'region']], on='store_id', how='left')
    df['text_raw'] = df['text_raw'].fillna('').astype(str)
    df['has_store'] = df['region'].notna()
    df['has_ts'] = df['ts'].notna()
    reason = pd.Series('', index=df.index)
    reason[df['text_raw'].str.strip() == ''] = 'empty_text'
    reason[df['record_id'].duplicated(keep='first')] = 'duplicate_record_id'
    good, bad = df[reason == ''].copy(), df[reason != ''].assign(reason=reason[reason != ''])
    out = ROOT / cfg['paths']['interim']
    out.mkdir(parents=True, exist_ok=True)
    good.to_parquet(out / 'records.parquet')
    bad.to_parquet(out / 'quarantine.parquet')
    report = {
        'rows_per_channel': good['channel'].value_counts().to_dict(),
        'quarantined': bad['reason'].value_counts().to_dict(),
        'missing_ts_pct': round(100 * (~good['has_ts']).mean(), 2),
        'missing_store_pct': round(100 * (~good['has_store']).mean(), 2),
        'date_range': [str(good['ts'].min()), str(good['ts'].max())],
        'records_per_store': good.groupby('store_id').size().describe().round(1).to_dict(),
        'exact_duplicate_text_pct': round(100 * good.duplicated(['store_id', 'text_raw']).mean(), 2),
        'text_len_by_channel': good.groupby('channel')['text_raw'].apply(lambda s: s.str.len().describe().round(1).to_dict()).to_dict(),
    }
    json.dump(report, open(out / 'data_quality.json', 'w'), indent=2, default=str)
    print(json.dumps(report, indent=2, default=str))
Run it, read data_quality.json, and use it to answer items 1, 2, 7 of the Day-1 checklist. If data_mode in config is synthetic, the pipeline reads data/synthetic/records.parquet instead and skips this step.
6.3 Normalization (keep signals, never erase negation)
Rules: keep raw text; keep negation words (not, nahi, illai, nako); never drop stop words; turn emojis into tokens instead of deleting them; shrink elongations but keep the emphasis (sooooo becomes soo); map spelling variants to one canonical form; no translation.
# src/storesignal/normalize.py
import re, unicodedata, emoji, yaml
from .config import ROOT

_N = yaml.safe_load(open(ROOT / 'config' / 'normalization.yaml', encoding='utf-8'))
_ABBR = _N['abbreviations']
_VAR = {v: canon for canon, vs in _N['variants'].items() for v in vs}
_REPEAT = re.compile(r'(.)\1{2,}')
_TOKEN = re.compile(r'[\w\']+|[^\w\s]')

def normalize(text):
    t = unicodedata.normalize('NFKC', str(text))
    t = emoji.demojize(t, delimiters=(' emoji_', ' '))      # an angry-face emoji becomes the token emoji_enraged_face
    t = _REPEAT.sub(r'\1\1', t.lower())
    out = []
    for w in _TOKEN.findall(t):
        w = _VAR.get(w, w)
        out.append(_ABBR.get(w, w))
    return ' '.join(out)

6.4 PII masking
# src/storesignal/pii.py
import re
_PHONE = re.compile(r'(?<!\d)(?:\+?91[\s-]?)?[6-9]\d{9}(?!\d)')
_EMAIL = re.compile(r'[\w.+-]+@[\w-]+\.[\w.-]+')
_URL = re.compile(r'https?://\S+')

def mask_pii(t):
    t = _EMAIL.sub('[EMAIL]', t)
    t = _URL.sub('[URL]', t)
    return _PHONE.sub('[PHONE]', t)
If the organizers provide a staff roster, also replace each staff name with [STAFF]. Models and rules read text_norm; people read only text_masked.
6.5 Language-pattern tag (for slicing metrics only)
# src/storesignal/langid.py
import re
_DEV = re.compile(r'[\u0900-\u097F]')
_TAM = re.compile(r'[\u0B80-\u0BFF]')
HI = set('nahi kya hai bahut accha kharab thanda garam paisa wala hain bhi aur'.split())
TA = set('romba illai nalla mosam enna inga sapadu'.split())
MR = set('khup aahe ahe kay changla majha'.split())

def lang_pattern(t):
    if _DEV.search(t) or _TAM.search(t):
        return 'native_script'
    w = set(t.split())
    h, ta, m = len(w & HI), len(w & TA), len(w & MR)
    if h + ta + m == 0:
        return 'english'
    if sum(x > 0 for x in (h, ta, m)) > 1:
        return 'mixed'
    return 'hinglish' if h else 'romanized_tamil' if ta else 'romanized_marathi'
This is a rough heuristic. It exists so Section 13 can report quality per pattern (english, hinglish, romanized_tamil, romanized_marathi, mixed, native_script). It never drives routing.
6.6 Embeddings
# src/storesignal/embed.py
import numpy as np, torch
from sentence_transformers import SentenceTransformer

def get_model(name='intfloat/multilingual-e5-small'):
    device = 'mps' if torch.backends.mps.is_available() else 'cpu'
    return SentenceTransformer(name, device=device)        # if MPS errors, force device='cpu'

def embed(texts, model, batch=64):
    X = model.encode(['query: ' + t for t in texts], batch_size=batch,
                     normalize_embeddings=True, show_progress_bar=True)
    return X.astype('float32')
Run once on text_norm, save with np.save('data/interim/embeddings.npy', E), and reload afterwards. Rows stay aligned with records_norm.parquet (same order). Because vectors are normalized, cosine similarity is just a matrix product.
6.7 Synthetic data generator (for development, tests and a fallback demo)
You will build and debug for days before you trust the real data. This generator makes about 30k records across four channels, 40 stores of different sizes, code-mixed text with typos and emojis, and three planted incidents that are entirely yours (they are not the organizers’ seeded incidents). Everything it creates carries is_synthetic=True, and the UI shows a banner whenever it is used.
# src/storesignal/synth.py   SYNTHETIC data only. Never present its numbers as real results.
import json
import numpy as np, pandas as pd
from pathlib import Path

rng = np.random.default_rng(42)
T = {
    'freezer_failure':   ['freezer not cooling, ice cream melted', 'freezer thanda nahi kar raha, kulfi pighal gayi', 'freezer romba noisy, ice cream melt aayiduchu'],
    'rude_billing':      ['billing guy was very rude to me', 'billing wale ne badtameezi se baat ki', 'billing counter la romba rude ah pesinanga'],
    'allergen_mislabel': ['label said nut free but my son had a reaction', 'packet pe nut free likha tha par peanuts the, allergy ho gayi'],
    'out_of_stock':      ['milk out of stock again', 'bread khatam ho gaya, kal bhi nahi tha'],
    'long_queue':        ['queue is too long, only one counter open', 'line bahut lambi hai, ek hi counter chalu'],
    'app_crash':         ['app crashes at checkout', 'app checkout pe hang ho jata hai'],
    'price_mismatch':    ['shelf price different from bill', 'shelf pe aur bill me alag price'],
    'dirty_floor':       ['floor was wet and dirty near the entrance', 'floor gandi aur geeli thi'],
}
BASE = {'out_of_stock': .30, 'long_queue': .25, 'app_crash': .15, 'price_mismatch': .15,
        'dirty_floor': .05, 'rude_billing': .04, 'freezer_failure': .03, 'allergen_mislabel': .005}
INCIDENTS = [
    {'store': 'S07', 'issue': 'freezer_failure',   'start': 80, 'len': 6, 'per_day': 2.0},
    {'store': 'S12', 'issue': 'allergen_mislabel', 'start': 90, 'len': 5, 'per_day': 0.8},
    {'store': 'S03', 'issue': 'rude_billing',      'start': 95, 'len': 7, 'per_day': 1.5},
]

def noisy(t):
    if rng.random() < .08 and len(t) > 6:
        i = int(rng.integers(1, len(t) - 2))
        t = t[:i] + t[i + 1:]                                  # drop a character (typo)
    if rng.random() < .15:
        t += ' ' + str(rng.choice(['😡', '🙁', '!!!', '...']))
    return t

def style(ch, t):
    return {'staff_note': 'shift note: ', 'call': 'customer called about: '}.get(ch, '') + t

def make(days=120, n_stores=40, incidents=None):
    start = pd.Timestamp('2026-05-01', tz='UTC')
    stores = pd.DataFrame({'store_id': [f'S{i:02d}' for i in range(1, n_stores + 1)],
                           'region': [['North', 'South', 'West', 'East'][i % 4] for i in range(n_stores)],
                           'size': rng.choice([0.4, 1.0, 2.5], size=n_stores, p=[.4, .4, .2])})
    issues = list(BASE)
    p = np.array(list(BASE.values()))
    p = p / p.sum()
    rows = []
    for d in range(days):
        for s in stores.itertuples():
            for _ in range(rng.poisson(6 * s.size)):
                rows.append((d, s.store_id, str(rng.choice(issues, p=p)), False))
    for inc in incidents or []:
        for d in range(inc['start'], inc['start'] + inc['len']):
            for _ in range(rng.poisson(inc['per_day'])):
                rows.append((d, inc['store'], inc['issue'], True))
    out = []
    for i, (d, s, issue, planted) in enumerate(rows):
        ch = str(rng.choice(['review', 'app', 'staff_note', 'call'], p=[.3, .3, .2, .2]))
        ts = start + pd.Timedelta(days=d, minutes=int(rng.integers(0, 1440)))
        out.append({'record_id': f'{ch}-{i}', 'channel': ch, 'ts': ts, 'store_id': s,
                    'text_raw': style(ch, noisy(str(rng.choice(T[issue])))),
                    'rating': float(rng.integers(1, 4)), 'true_issue': issue,
                    'planted': planted, 'is_synthetic': True})
    df = pd.DataFrame(out).merge(stores[['store_id', 'region']], on='store_id')
    return df.sort_values('ts').reset_index(drop=True)

if __name__ == '__main__':
    Path('data/synthetic').mkdir(parents=True, exist_ok=True)
    make(incidents=INCIDENTS).to_parquet('data/synthetic/records.parquet')
    json.dump(INCIDENTS, open('data/synthetic/ground_truth_incidents.json', 'w'))
The columns true_issue and planted exist only so your own tests can check the system. The pipeline never reads them, which keeps the test honest. Real seeded incidents may ramp up gradually instead of arriving at a constant rate, so Section 9.3 also tests ramps.
6.8 Splits and leakage rules
Near-duplicates must stay on one side of any split, so assign dup_group_id (Section 10) first and split by group.
Classifier: train on pseudo-labels or labeled data, evaluate on your hand-labelled dev set. The dev set is never used for training until the final refit.
Radar: tune on the first 70% of the timeline using synthetic injection (Section 9.3), then estimate false alerts on the remaining 30%.
The hidden labels are touched only through evaluate.py, and every run is logged (Section 13.5).
Done when: data_quality.json exists; per-channel row counts match the raw files; normalize() passes unit tests (idempotent, keeps negation, keeps emoji tokens); the synthetic generator produces a dataset the later stages can read.
7. Issue classification, severity and actionability (Module B)
7.1 What to predict
Issue: one primary category (softmax over the taxonomy), plus a second candidate with its probability. Report the second only if its probability is above a threshold, which gives light multi-label behavior.
Severity: four levels: low, medium, high, critical.
Actionability: yes/no, meaning a practical issue someone can check or fix.
Owner: never predicted. It is looked up from the taxonomy (Section 11).
Uncertainty: needs_review when confidence is low (Section 7.5). Ambiguous records go to a human instead of being forced into a category.
7.2 taxonomy.yaml ⚠
Copy ids, names and owners exactly from the organizers’ taxonomy. You add the description, keywords and examples yourself. That is not a label leak: it is domain knowledge about the categories.

7.3 Which labeling scenario are you in?
Scenario B, step by step
Keyword votes: count seed keywords per issue (fast regex).
Prototype votes: embed each issue’s description and example texts, average them into one prototype vector, and score every record by cosine similarity to each prototype.
Combine: blend the two into a probability-like score and pseudo-label only the confident records, capped per class so big classes do not dominate.
Train the hybrid model (Section 7.5) on the pseudo-labels.
Hand-label about 400 dev records with the Label Tool page (Section 14): roughly 12–15 per category, plus 60 random records and 60 policy hits. Budget 2–3 hours. This is your honest measuring stick.
Self-train once: predict the unlabeled records, add the confident new predictions, refit.
Final fit on pseudo-labels plus your dev labels.
Using evaluate.py to tune the model would be using hidden labels to tune. Run it sparingly on finished candidate models, log each run, and tune on your own dev set instead.
# src/storesignal/weak_labels.py
import re
import numpy as np
from .embed import embed

def keyword_votes(texts, issues):
    V = np.zeros((len(texts), len(issues)), dtype='float32')
    for j, it in enumerate(issues):
        pat = re.compile(r'\b(?:' + '|'.join(re.escape(k.lower()) for k in it['seed_keywords']) + r')\b')
        V[:, j] = [len(pat.findall(t)) for t in texts]
    return V

def prototype_scores(E, model, issues):
    protos = []
    for it in issues:
        P = embed([it['description']] + it.get('example_texts', []), model)
        c = P.mean(axis=0)
        protos.append(c / np.linalg.norm(c))
    return E @ np.stack(protos).T                       # cosine, shape (records, issues)

def softmax(z):
    z = np.exp(z - z.max(axis=1, keepdims=True))
    return z / z.sum(axis=1, keepdims=True)

def weak_labels(V, S, w_kw=1.0, w_emb=2.0, temp=50.0):
    kw = V / (V.sum(axis=1, keepdims=True) + 1e-6)
    emb = softmax(S * temp)
    score = (w_kw * kw + w_emb * emb) / (w_kw * (V.sum(axis=1) > 0) + w_emb)[:, None]
    return score.argmax(axis=1), score.max(axis=1)      # label index, confidence
Gotcha: e5 cosine similarities all sit in a narrow high band (about 0.7 to 0.9). Use relative scores (softmax with a large temperature, as above), never an absolute cosine cut-off.

# src/storesignal/classify.py
import numpy as np, pandas as pd, scipy.sparse as sp
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.linear_model import LogisticRegression
from sklearn.pipeline import FeatureUnion

def make_vectorizer():
    return FeatureUnion([
        ('char', TfidfVectorizer(analyzer='char_wb', ngram_range=(2, 5), min_df=3, sublinear_tf=True, max_features=300000)),
        ('word', TfidfVectorizer(analyzer='word', ngram_range=(1, 2), min_df=2, sublinear_tf=True, token_pattern=r'[\w\']+')),
    ])

def _stack(vec_out, E, w):
    return sp.hstack([vec_out, sp.csr_matrix(E * w)]).tocsr()

def fit(texts, E, y, emb_weight=1.0, C=4.0):
    vec = make_vectorizer()
    X = _stack(vec.fit_transform(texts), E, emb_weight)
    clf = LogisticRegression(C=C, max_iter=3000, class_weight='balanced').fit(X, y)
    return {'vec': vec, 'clf': clf, 'w': emb_weight}

def predict(m, texts, E):
    P = m['clf'].predict_proba(_stack(m['vec'].transform(texts), E, m['w']))
    order = np.argsort(-P, axis=1)
    cls = m['clf'].classes_
    i1, i2 = order[:, 0], order[:, 1]
    r = np.arange(len(P))
    return pd.DataFrame({'issue': cls[i1], 'p1': P[r, i1], 'issue2': cls[i2], 'p2': P[r, i2],
                         'margin': P[r, i1] - P[r, i2]})
Uncertainty threshold. On the dev set, sweep τ from 0.3 to 0.9. For each τ compute accuracy on records with p1 >= tau and the share of records kept (coverage). Pick the smallest τ whose accepted accuracy meets your target (start with 0.90). Everything below τ is flagged needs_review = True. Plot accuracy against coverage for the Trust page.

8.2 Engine
# src/storesignal/policy.py
import re, yaml
from .config import ROOT

def _compile(p):
    p = p.lower()
    if p.endswith('*'):
        return re.compile(r'\b' + re.escape(p[:-1]) + r'\w*')
    return re.compile(r'\b' + re.escape(p) + r'\b')

class PolicyEngine:
    def __init__(self, path=None):
        spec = yaml.safe_load(open(path or ROOT / 'config' / 'policy_rules.yaml', encoding='utf-8'))
        self.neg = set(spec['negation_cues'])
        self.cats = {c: {**v, 'rx': [(_compile(p), p) for p in v['patterns']]} for c, v in spec['categories'].items()}

    def scan(self, text_norm):
        hits = []
        for cat, v in self.cats.items():
            for rx, pat in v['rx']:
                for m in rx.finditer(text_norm):
                    before = text_norm[:m.start()].split()[-3:]
                    after = text_norm[m.end():].split()[:2]      # Hindi, Marathi, Tamil put the negation after the noun
                    negated = any(w in self.neg for w in before + after)
                    hits.append({'category': cat, 'pattern': pat, 'span': m.group(0), 'negated': negated})
        return hits
8.3 Rules of the road
Never silence a hit. A record with a non-negated hit is policy_flag. A record whose hits are all negated (for example ‘no cockroach, very clean’) is policy_weak: it goes to a low-priority review queue, it is not deleted and it does not raise an alert by itself.
Volume is irrelevant. One flagged record creates an alert. Further flagged records for the same store and category within 7 days attach to the same alert as corroborating evidence.
Dedupe cannot hide a risk. Duplicate groups carry policy_any = True if any member was flagged.
Honest wording. Policy alerts say ‘needs human review, unverified’, show the matched words and quote the rule’s escalation text.
Severity floor. The category’s severity_floor is applied in severity() from Section 7.6.
8.4 Semantic safety net (catches spellings your rules miss)
Write 10–15 short prototype sentences per safety category in English, Hinglish and romanized Tamil/Marathi. Embed them, score every record by its maximum cosine similarity to those prototypes, and flag records that sit in the top 0.5% of scores and were not caught by a regex. Because e5 cosines are compressed, use that percentile cut-off instead of a fixed number. These go to the review queue as ‘possible risk (semantic)’. They are never auto-escalated.

9. Early-Warning Radar (Module C): the signature feature
9.1 The idea
For every store and every issue, ask one question: is the number of unique reports in the last few days unusually high compared with this store’s own history, given how much feedback this store normally receives? Raise an alert the moment the answer becomes yes, using only the data that existed at that moment.
9.2 The statistical model
Definitions (all counts are unique report groups after deduplication, Section 10):
Series: reports of issue c at store s.
Exposure proxy E: the store’s total unique reports (all issues, all channels) in a window. This is a documented stand-in for footfall. If the organizers supply real visits or transactions, replace E with them and say so.
Windows: recent window W (default 3 days) and baseline window L (default 28 days) immediately before it.
k: reports of (s, c) in the recent window.
Baseline rate: λ = (K_past + α·π_c) / (E_past + α), where K_past is the (s, c) count in the baseline window, E_past is the store total in that window, π_c is the global share of issue c, and α (default 50) is the strength of the prior. This shrinks small or new stores toward the global rate (empirical Bayes) so a store with no history does not flag everything.
Expected count: μ = max(λ · E_recent · φ, μ_min), with φ = 1.3 as an over-dispersion cushion and μ_min = 0.3 as a floor.
Tail probability: p = P(Poisson(μ) ≥ k). Ratio = k / μ.
Fire when k ≥ k_min (3) and p ≤ p_thr (0.001) and ratio ≥ 3 and the warm-up period (14 days) is over.
Why it behaves well: a large store with ten freezer complaints a week is not alarmed by twelve. A small store that normally has none is alarmed by three. Exposure ties the expected count to the store’s own activity level. The detector is evaluated each time a new report arrives, so it reports the earliest moment it could have fired, which is what lead time rewards.
Which records feed the radar: unique groups whose top issue has p1 >= min_conf (default 0.35). Policy alerts are a separate mechanism and do not depend on this series.

# src/storesignal/radar.py
from bisect import bisect_right
from collections import defaultdict
import pandas as pd
from scipy.stats import poisson

def _count(lst, lo, hi):
    return bisect_right(lst, hi) - bisect_right(lst, lo)         # items with lo < t <= hi

def run_radar(df, p):
    '''df: unique report groups sorted by ts, columns ts, store_id, issue, group_id.
    p: the radar config dict. Causal: row i is judged using only rows 0..i.'''
    day = pd.Timedelta(days=1)
    t0 = df['ts'].min()
    ev, st, gl, allv = defaultdict(list), defaultdict(list), defaultdict(list), []
    n_issues = df['issue'].nunique()
    W, L = p['window_days'], p['lookback_days']
    open_alerts, alerts = {}, []
    for row in df.itertuples():
        t = (row.ts - t0) / day                                  # float days since the first record
        s, c = row.store_id, row.issue
        ev[(s, c)].append(t)
        st[s].append(t)
        gl[c].append(t)
        allv.append(t)
        k = _count(ev[(s, c)], t - W, t)
        if k < p['k_min'] or t < p['warmup_days']:
            continue
        e_rec = _count(st[s], t - W, t)
        k_past = _count(ev[(s, c)], t - W - L, t - W)
        e_past = _count(st[s], t - W - L, t - W)
        pi_c = (_count(gl[c], t - W - L, t - W) + 1) / (_count(allv, t - W - L, t - W) + n_issues)
        lam = (k_past + p['alpha'] * pi_c) / (e_past + p['alpha'])
        mu = max(lam * e_rec * p['phi'], p['mu_min'])
        pval = float(poisson.sf(k - 1, mu))
        if pval > p['p_thr'] or k / mu < p['ratio_min']:
            continue
        a = open_alerts.get((s, c))
        if a and t - a['last_t'] <= p['cooldown_days']:           # same episode: update, do not re-alert
            a.update(last_t=t, last_ts=row.ts, k=max(a['k'], k), p_min=min(a['p_min'], pval))
        else:
            a = {'store_id': s, 'issue': c, 'first_ts': row.ts, 'first_t': t, 'last_t': t, 'last_ts': row.ts,
                 'k': k, 'mu': mu, 'ratio': k / mu, 'p_min': pval}
            open_alerts[(s, c)] = a
            alerts.append(a)
    return alerts
Evidence is not stored inside the radar. Section 11 collects every report of that store and issue between first_ts - W and last_ts.
9.4 Tuning without hidden labels: synthetic injection
You do not know how big the seeded incidents are, and you must not peek at them. So you teach the detector what ‘small but rising’ means by planting your own incidents into copies of your own data.
Calibration period: the first 70% of the timeline (after warm-up). Run the radar on it. Every alert counts as a false alert, which is conservative because some may be real. This gives false alerts per store-week.
Inject about 100 incidents: random (store, issue) pairs with at least 20 reports of that issue overall; sizes n of 3, 4, 6, 8 reports over 1, 3 or 5 days; both a constant rate and a ramp (intensity increasing over time). Reuse real texts of that issue so the injected text looks real.
Score: detection rate (an alert for that store and issue between injection start and two days after its end) and median delay in hours from injection start.
Grid-search window_days ∈ {3, 5, 7}, k_min ∈ {3, 4, 5}, p_thr ∈ {1e-2, 1e-3, 1e-4}, ratio_min ∈ {2, 3, 4}. Save everything to reports/radar_grid.csv.
Choose the cheapest setting with false alerts at or under 0.05 per store-week (about one per store every 20 weeks) and detection of at least 90% for n=6 over 3 days, then prefer the lowest delay. These targets are starting points. Explain your choice in the demo.
import numpy as np, pandas as pd

def inject(df, store, issue, start, n, days, ramp, rng):
    '''Copy of df plus n extra reports of (store, issue) over `days` days from `start` (tz-aware Timestamp).'''
    pool = df[df['issue'] == issue]
    u = rng.random(n)
    offs = np.sort(days * (np.sqrt(u) if ramp else u))              # sqrt(u): more events later = a ramp
    new = pool.sample(n, replace=True, random_state=int(rng.integers(1_000_000_000))).copy()
    new['store_id'] = store
    new['ts'] = start + pd.to_timedelta(offs, unit='D')
    new['group_id'] = ['inj-%s-%s-%d' % (store, issue, i) for i in range(n)]
    return pd.concat([df, new]).sort_values('ts').reset_index(drop=True)

def injection_delay_hours(df, store, issue, start, n, days, ramp, params, rng):
    sl = df[(df['ts'] >= start - pd.Timedelta(days=35)) & (df['ts'] <= start + pd.Timedelta(days=days + 3))]
    sl = inject(sl, store, issue, start, n, days, ramp, rng)         # slicing keeps each trial fast
    end = start + pd.Timedelta(days=days + 2)
    hits = [a for a in run_radar(sl, params) if a['store_id'] == store and a['issue'] == issue and start <= a['first_ts'] <= end]
    return min((a['first_ts'] - start).total_seconds() / 3600 for a in hits) if hits else None   # None = missed
Run time: roughly a second per trial, so 100 trials × a 27-point grid is tens of minutes. Use joblib.Parallel or shrink the grid. Your own synthetic planted incidents from Section 6.7 are a second, independent check.

10. Deduplication, incident fusion and the connection graph (Module D)
10.1 Two different things
A duplicate is the same message repeated (copy-paste, an app resubmit, one ticket logged twice). Corroboration is different people or channels describing the same event. Duplicates must not inflate counts. Corroboration should raise confidence. The stretch goal ‘appears once’ is met by one incident card that lists all its reports and channels.
10.2 Three layers
The radar counts S1+S2 groups. Alerts, briefs and the UI show S3 clusters. The thresholds are starting values: hand-check 50 pairs near each threshold and adjust. Add a family field to taxonomy.yaml (for example cold_chain, billing, safety) so the same event described under two neighboring issues still fuses.

# src/storesignal/dedupe.py
import hashlib
import numpy as np, pandas as pd
from rapidfuzz import fuzz

class UnionFind:
    def __init__(self, n):
        self.p = list(range(n))
    def find(self, x):
        while self.p[x] != x:
            self.p[x] = self.p[self.p[x]]
            x = self.p[x]
        return x
    def union(self, a, b):
        self.p[self.find(a)] = self.find(b)

def assign_groups(df, E, win_h=72, cos_dup=0.95, cos_fuse=0.80):
    '''df rows align with E (normalized embeddings). df needs store_id, ts, text_norm, family, entities (list).'''
    n = len(df)
    dup, inc = UnionFind(n), UnionFind(n)
    seen = {}
    for i, (s, t) in enumerate(zip(df['store_id'], df['text_norm'])):
        h = hashlib.md5((str(s) + '|' + t).encode('utf-8')).hexdigest()
        if h in seen:
            dup.union(i, seen[h])
        else:
            seen[h] = i
    texts, fam, ents = df['text_norm'].tolist(), df['family'].tolist(), df['entities'].tolist()
    for store, idx in df.groupby('store_id').indices.items():
        idx = idx[np.argsort(df['ts'].values[idx])]
        hrs = df['ts'].values[idx].astype('datetime64[s]').astype('int64') / 3600.0
        for a in range(len(idx)):
            for b in range(a + 1, len(idx)):
                if hrs[b] - hrs[a] > win_h:
                    break
                i, j = idx[a], idx[b]
                cos = float(E[i] @ E[j])
                if cos >= cos_dup or fuzz.ratio(texts[i], texts[j]) >= 92:
                    dup.union(i, j)
                if fam[i] == fam[j] and (cos >= cos_fuse or set(ents[i]) & set(ents[j])):
                    inc.union(i, j)
    out = df.copy()
    out['dup_group_id'] = ['d%d' % dup.find(i) for i in range(n)]
    out['incident_cluster_id'] = ['c%d' % inc.find(i) for i in range(n)]
    return out
Use fuzz.ratio (edit-distance similarity), not token_set_ratio: the latter scores a short message as identical to a longer one that contains it and would merge different reports.
Never lose a risk: after grouping, compute policy_any per dup_group_id and per incident_cluster_id (true if any member was policy-flagged), choose the earliest record as canonical, and keep every member linked. Nothing is deleted.

import re

def compile_entities(spec):
    words = [(w, re.compile(r'\b' + re.escape(w) + r'\b')) for w in spec['equipment'] + spec['products']]
    ids = {k: re.compile(v) for k, v in spec['id_patterns'].items()}
    return words, ids

def extract_entities(text_norm, compiled):
    words, ids = compiled
    ents = [w for w, rx in words if rx.search(text_norm)]
    for name, rx in ids.items():
        m = rx.search(text_norm)
        if m:
            ents.append(name + ':' + m.group(1))
    return ents

11. Alerts, routing, resolution tracker and feedback (Modules F, G, K, L)
11.1 The alert object
The confidence label is a transparent rule, not a calibrated probability, and the UI says so: high = at least two channels and (policy match or p ≤ 1e-5); medium = at least two channels or p ≤ 1e-4; otherwise low.
Explanation text is built from templates, never free-written:
Emerging: ‘{issue} at store {store}: {k} unique reports in {W} days versus about {mu} expected ({ratio}x, p={p}). Channels: {channels}. Possible common {family} issue, cause not confirmed.’
Policy: ‘Policy match [{category}] on: {matched words}. {n} report(s) across {n_ch} channel(s). Needs human review, unverified. Escalation rule: {rule}.’
# src/storesignal/alerts.py
import pandas as pd

def emerging_alert(a, rec, route, W):
    lo = a['first_ts'] - pd.Timedelta(days=W)
    ev = rec[(rec['store_id'] == a['store_id']) & (rec['issue'] == a['issue'])
             & (rec['ts'] >= lo) & (rec['ts'] <= a['last_ts'])].sort_values('ts')
    return {
        'alert_id': 'E-%s-%s-%s' % (a['store_id'], a['issue'], a['first_ts'].strftime('%Y%m%d%H%M')),
        'tier': 'emerging', 'store_id': a['store_id'], 'issue': a['issue'],
        'owner': route['owner'], 'cc': route.get('cc', []), 'severity': route['severity'],
        'alert_ts': a['first_ts'], 'first_signal_ts': ev['ts'].min(),
        'n_reports': len(ev), 'n_unique': int(ev['dup_group_id'].nunique()),
        'channels': sorted(ev['channel'].unique()),
        'why': {'k': a['k'], 'expected': round(a['mu'], 2), 'ratio': round(a['ratio'], 1),
                'p': a['p_min'], 'window_days': W, 'pattern_id': a.get('pattern_id')},
        'evidence': ev[['record_id', 'channel', 'ts', 'text_masked']].head(10).to_dict('records'),
        'action': route['first_action'], 'escalation_rule': route['escalation_rule'],
    }

def policy_alerts(hits, rec, spec, gap_days=7):
    '''hits: non-negated policy hits (record_id, category, span). One alert per store, category and episode.'''
    h = hits.merge(rec[['record_id', 'store_id', 'ts', 'channel', 'text_masked', 'dup_group_id']], on='record_id').sort_values('ts')
    out = []
    for (store, cat), g in h.groupby(['store_id', 'category']):
        cur = []
        for r in g.itertuples():
            if cur and (r.ts - cur[-1].ts).days > gap_days:
                out.append(_policy_alert(store, cat, cur, spec))
                cur = []
            cur.append(r)
        if cur:
            out.append(_policy_alert(store, cat, cur, spec))
    return out

def _policy_alert(store, cat, rows, spec):
    pc = spec['categories'][cat]
    chans = sorted({r.channel for r in rows})
    return {
        'alert_id': 'P-%s-%s-%s' % (store, cat, rows[0].ts.strftime('%Y%m%d%H%M')),
        'tier': 'policy', 'store_id': store, 'issue': cat, 'owner': pc['owner'], 'cc': pc.get('cc', []),
        'severity': pc['severity_floor'], 'alert_ts': rows[0].ts,
        'n_reports': len(rows), 'n_unique': len({r.dup_group_id for r in rows}), 'channels': chans,
        'why': {'policy_category': cat, 'matched': sorted({r.span for r in rows}), 'corroborated': len(chans) > 1},
        'evidence': [{'record_id': r.record_id, 'channel': r.channel, 'ts': r.ts, 'text_masked': r.text_masked} for r in rows[:10]],
        'escalation_rule': 'MANDATORY POLICY [' + cat + ']: ' + pc['escalation'],
        'note': 'Needs human review. Unverified report.',
    }
Alert ids are built from store, issue and first time, so re-running the pipeline produces the same ids and the tracker never creates duplicates.

# src/storesignal/routing.py
SEV = {'low': 0, 'medium': 1, 'high': 2, 'critical': 3}

def route_for(issue, policy_cats, routes, policy_spec):
    r = dict(routes['routes'].get(issue, routes['default']))
    for cat in policy_cats:                        # mandatory rules are deterministic and always win
        pc = policy_spec['categories'][cat]
        if SEV[pc['severity_floor']] > SEV[r['severity']]:
            r['severity'] = pc['severity_floor']
        r['owner'], r['cc'] = pc['owner'], pc.get('cc', [])
        r['escalation_rule'] = 'MANDATORY POLICY [' + cat + ']: ' + pc['escalation']
    return r

def upsert_alert(con, a, region, sla_hours):
    due = (a['alert_ts'] + dt.timedelta(hours=sla_hours)).isoformat()
    con.execute('INSERT OR IGNORE INTO alerts (alert_id, tier, store_id, region, issue, severity, owner, alert_ts, sla_due, payload_json) VALUES (?,?,?,?,?,?,?,?,?,?)',
                (a['alert_id'], a['tier'], a['store_id'], region, a['issue'], a['severity'], a['owner'],

def set_status(con, alert_id, to_status, actor, note=''):
    cur = con.execute('SELECT status FROM alerts WHERE alert_id=?', (alert_id,)).fetchone()[0]
    con.execute('UPDATE alerts SET status=? WHERE alert_id=?', (to_status, alert_id))
    con.execute('INSERT INTO events (alert_id, ts, actor, from_status, to_status, note) VALUES (?,?,?,?,?,?)',
                (alert_id, now(), actor, cur, to_status, note))
    con.commit()

def override_owner(con, alert_id, new_owner, actor, reason):
    cur = con.execute('SELECT owner, status FROM alerts WHERE alert_id=?', (alert_id,)).fetchone()
    con.execute('UPDATE alerts SET owner=? WHERE alert_id=?', (new_owner, alert_id))
    con.execute('INSERT INTO events (alert_id, ts, actor, from_status, to_status, note) VALUES (?,?,?,?,?,?)',
                (alert_id, now(), actor, cur[1], cur[1], 'owner %s -> %s: %s' % (cur[0], new_owner, reason)))
    con.commit()

def overdue(con):
    return con.execute("SELECT alert_id, owner, sla_due FROM alerts WHERE status != 'Resolved' AND sla_due < ?", (now(),)).fetchall()

12. Regional brief generator (Module H)
12.1 What one page contains (R5 outputs 1 and 2)
Header: region, week (Monday to Sunday), data coverage (records, channels, stores reporting).
Executive summary: three bullets built from counts by a template.
Top 5 issues: rank, issue, severity, owner, affected stores, trend arrow vs last week, one or two evidence quotes, the stated escalation rule, the next action.
Safety and compliance box: every open policy alert in the region, not limited to five.
Emerging signals: alerts opened this week, small-but-rising issues, cross-store patterns.
Actions due and overdue: from the tracker.
Data caveats: proxy exposure, share of low-confidence classifications, percent of records missing store or time.
12.2 Ranking is not raw volume
Sort key: (has an open policy alert, severity rank, emerging score, share excess, unique reports), all descending. Emerging score is the largest value of -log10(p) among the region’s open alerts for that issue (0 if none). Share excess is this week’s share of the region’s reports for that issue minus its four-week average share. Take the first five. The safety box is separate, so no policy item is ever cut by the top-5 limit.
12.3 Trend arrow
def trend(cur, prev, cur_total, prev_total, emerging):
    if emerging:
        return '▲▲'                                         # an emerging alert opened this week
    if prev == 0 and cur >= 3:
        return 'NEW'
    sc, sp = cur / max(cur_total, 1), prev / max(prev_total, 1)
    if sp > 0 and sc / sp >= 1.25 and cur - prev >= 2:
        return '▲'
    if sp > 0 and sc / sp <= 0.8 and prev - cur >= 2:
        return '▼'
    return '▬'
Comparing shares, not raw counts, keeps a busy week from looking like a worsening one.
12.4 Evidence quotes
Pick up to two reports per issue from different channels, closest to the cluster centroid. Quote the masked text, cut to 140 characters, in its original language, without editing a word.
import numpy as np

def pick_quotes(rows, E_rows, k=2):
    c = E_rows.mean(axis=0)
    c = c / np.linalg.norm(c)
    order = np.argsort(-(E_rows @ c))
    chosen, seen = [], set()
    for i in order:
        ch = rows.iloc[i]['channel']
        if ch in seen and len(seen) < rows['channel'].nunique():
            continue                                           # prefer a new channel first
        chosen.append(rows.iloc[i])
        seen.add(ch)
        if len(chosen) == k:
            break
    return [(r['channel'], r['text_masked'][:140]) for r in chosen]

import re, json

def numbers(s):
    return set(re.findall(r'\d+(?:\.\d+)?', s))

def verify(text, facts):
    return numbers(text) <= numbers(json.dumps(facts, default=str))      # no number the facts do not contain

def polish(bullets, facts):                                               # optional: pip install ollama
    import ollama
    prompt = ('Reword these bullets in plain concise English as bullets without numbering. '
              'Do not add, remove or change any number, store, cause or action.\n' + '\n'.join(bullets))
    out = ollama.chat(model='llama3.2:3b', messages=[{'role': 'user', 'content': prompt}])['message']['content']
    return out if verify(out, facts) else '\n'.join(bullets)             # fall back to the template text

# src/storesignal/metrics.py
import numpy as np
from sklearn.metrics import f1_score, classification_report

def classification_metrics(y_true, y_pred, meta):
    y_true, y_pred = np.asarray(y_true), np.asarray(y_pred)
    out = {'macro_f1': float(f1_score(y_true, y_pred, average='macro')),
           'weighted_f1': float(f1_score(y_true, y_pred, average='weighted')),
           'report': classification_report(y_true, y_pred, output_dict=True, zero_division=0)}
    for col in ['channel', 'lang_pattern']:
        out['by_' + col] = {g: float(f1_score(y_true[idx], y_pred[idx], average='macro'))
                            for g, idx in meta.groupby(col).indices.items() if len(idx) >= 20}
    return out

def ece(conf, correct, bins=10):
    conf, correct = np.asarray(conf, dtype=float), np.asarray(correct, dtype=float)
    edges = np.linspace(0, 1, bins + 1)
    total = 0.0
    for lo, hi in zip(edges[:-1], edges[1:]):
        m = (conf > lo) & (conf <= hi)
        if m.any():
            total += m.mean() * abs(correct[m].mean() - conf[m].mean())
    return float(total)

def wilson(k, n, z=1.96):
    if n == 0:
        return (0.0, 0.0)
    p = k / n
    d = 1 + z * z / n
    c = p + z * z / (2 * n)
    h = z * ((p * (1 - p) / n + z * z / (4 * n * n)) ** 0.5)
    return ((c - h) / d, (c + h) / d)

    steps.append((t_alert, 'Recommended: ' + a.get('action', a['escalation_rule'])))
    return sorted(steps, key=lambda s: s[0])

def baseline_fire(ts, k=5, days=7):
    ts = sorted(ts)
    for i in range(k - 1, len(ts)):
        if ts[i] - ts[i - k + 1] <= pd.Timedelta(days=days):
            return ts[i]
    return None

22. Complete specifications of every remaining module
These specifications close the gaps listed in Section 20. Each one gives purpose, input, output, steps, edge cases and a test, so you can write the file yourself. 22.1 inspect_data.py (data profiler, gate G1)
Purpose: tell you in two minutes what an unknown file looks like.
Input: a folder, default data/raw. Output: console report and reports/profile.md.
Steps: for every csv, tsv, xlsx, json or jsonl file: (1) read it with the loader in 22.3; (2) print the file name, row count and columns; (3) for each column guess the type (id, datetime, number, short text, long text, category) and print percent missing, unique count and three sample values; (4) for each text column print length percentiles (min, median, 95th, max), the most common exact length (a clue to a truncation cap), the percent with emoji, the percent in Devanagari or Tamil script, the percent non-ASCII and the language-pattern shares from Section 6.5; (5) for each datetime guess print the parse success under day-first and month-first, the min and max, and whether a time of day is present; (6) for store-like columns print the number of unique stores and the overlap with the store master; (7) print the exact-duplicate rate of the text.
Edge cases: very large files, profile the first 50,000 rows. Encoding errors: try utf-8, utf-8-sig, cp1252, latin-1 in that order and report which worked.
Test: run it on the four messy synthetic copies. It must name the date, store and text columns correctly in every copy.
22.2 automap.py (column mapper, gate G2)
Purpose: propose the CHANNELS mapping so final-day mapping is a ten-minute check.
Input: the profile of each file. Output: config/mapping_suggested.yaml and a printed table with a confidence per column.
Steps: score every column for every target, pick the best one, mark confidence high (name and content agree), medium (one agrees) or low (neither), write the YAML and print every low-confidence choice for you to fix by hand.
Test: the four messy copies must map correctly.
22.3 Multi-format loader (inside ingest.py)
read_any(path) reads by extension: csv or tsv with delimiter sniffing, xlsx through pandas, json or jsonl through read_json (lines for jsonl). Always read as text, strip a BOM, try the encoding list from 22.1.
Date parsing: try ISO format first. Otherwise parse both day-first and month-first and keep the one with the higher success rate. If any value has a first field above 12, day-first is certain. On a tie use day-first. Log the decision and the success rates in data_quality.json.
22.4 normalize.run()
Load records.parquet.
text_masked = mask_pii(text_raw), then text_norm = normalize(text_masked), so personal data never reaches a model.
lang_pattern from text_norm.
is_truncated: per channel, if the most common text length covers at least 1% of rows and is at least 100 characters, treat it as a cap and mark records at or above it. Also mark texts ending with an ellipsis.
Sort by (ts, record_id) with missing timestamps last. Write records_norm.parquet.
Write the 400 most frequent tokens that are not in the normalization dictionary to reports/unknown_tokens.txt.
Test: the row count equals records.parquet, and text_norm is never empty when text_raw is not.
22.5 embed.run()
Load records_norm.parquet and the model from the local cache (offline flag respected).
Embed text_norm in batches of 64 and save embeddings.npy (float32, normalized, same row order).
Save a small JSON with the model name, dimension, row count and a hash of the text_norm column. If the hash matches an existing cache, skip the work.
Edge cases: embed the word empty for blank text; fall back to CPU if MPS fails.
22.6 weak_labels.run()
Load the taxonomy, embeddings.npy and records_norm.parquet.
Compute keyword votes and prototype scores (Section 7.3) and combine them.
Keep records with confidence at or above weak.min_conf, capped at weak.cap_per_class per class.
Write weak_labels.parquet (record_id, issue, confidence, source: keyword, embedding or both).
Print counts per class and warn about any class with fewer than 30 examples (add keywords or examples for it).
Test: on synthetic data, print the weak-label accuracy against true_issue (tag it SYNTHETIC).
22.7 train.py
Training table: use the provided labels if there are any (Scenario A), otherwise the weak labels. Hand labels from dev_labels.csv replace weak labels for the same records and are repeated 3 times.
Hold-out: if there are at least 200 dev labels, hold half of them out for model selection. Otherwise use 5-fold cross-validation on the dev set. Split by dup_group_id when it exists.
Fit M1, M2 and M3 (Section 7.4) and write the macro-F1 of each to reports/model_comparison.csv.
Pick the best macro-F1; on a tie take the simpler model.
Tune τ on the held-out dev records (Section 7.5).
Refit the chosen model on everything and save models/clf.joblib with the class list and τ.
In Scenario A also fit severity and actionability models.
Optional self-training round: predict the unlabeled records, add those with p1 >= 0.9 (capped per class), refit, and keep the result only if dev macro-F1 does not drop.
Edge cases: classes missing from the training data are reported and dropped from predictions.
22.8 score.py
Load records_norm.parquet, embeddings.npy, the model, taxonomy, policy rules and routes.
Predict issue, p1, second issue and margin with classify.predict.
Run the policy engine on every text_norm. Write policy_hits.parquet (record_id, category, pattern, span, negated). Derive policy_flag (any non-negated hit), policy_weak (hits exist, all negated) and policy_cats.
Run the semantic safety net (22.10) and add semantic_flag.
Compute severity (Section 7.6) using the taxonomy default of the predicted issue, the policy floor, the rating and the text.
Compute actionability (Scenario A model, or the heuristic plus the dev-trained model in Scenario B).
Set needs_review when p1 < tau or the margin is small.
Extract entities and set the issue family from the taxonomy.
Run assign_groups for records that have a store and a time. Records without a store or time get their own group.
Propagate policy_any to each group, mark the earliest record in each duplicate group as canonical.
Write records_scored.parquet. Print counts: flagged, weak, needs_review, number of groups.
22.9 build_taxonomy.py (taxonomy matcher, gate G4)
Purpose: turn the organizers’ taxonomy into taxonomy.yaml and a draft routing.yaml quickly.
Input: the organizers’ taxonomy file in any format, and config/issue_library.yaml (the 30 demo issues from Section 21.2 with descriptions, keywords, examples, severity and mandatory flags). Output: config/taxonomy.yaml, a draft config/routing.yaml, reports/taxonomy_match.csv.
Steps: (1) read each organizer issue (id or name, owner function, definition if any); (2) embed name plus definition and find the most similar library entry; (3) accept a match only if it ranks clearly first and shares at least one keyword; (4) for matches copy description, keywords, examples and the mandatory flag from the library; (5) ids, names and owners always come from the organizers’ file, severity from their file if present, otherwise from the library; (6) unmatched issues get an empty description for you to write by hand; (7) if the organizers’ definition mentions safety, allergen, hygiene or misconduct, flag the issue mandatory even if the library does not; (8) write the match report with the similarity and a blank Review column, and the routing draft with owner, severity, a first-action template, the default escalation rule and the default SLA.
Review rule: you read every row of taxonomy_match.csv and fix the mistakes.
22.10 semantic.py (semantic safety net)
Input: embeddings.npy, config/safety_prototypes.yaml (10–15 short sentences per safety category in English, Hinglish and romanized Tamil or Marathi).
Steps: embed the prototypes; for each category take every record’s highest cosine to that category’s prototypes; flag records above the 99.5th percentile of that category that the regex did not flag; output semantic_flag and semantic_category.
Use: review queue only. It never raises an alert by itself.
22.11 radar.run()
Load records_scored.parquet. Keep records with a store and a time, canonical == True and p1 >= radar.min_conf.
Build the frame with columns ts, store_id, issue, group_id (the duplicate group), sorted by (ts, group_id).
Run run_radar with the config, then link_cross_store.
Convert timestamps to text and write radar_alerts.json.
Print the number of alerts and alerts per store-week.
Edge cases: if the data spans fewer days than warmup_days, print a warning and shorten the warm-up to a third of the span.
22.12 alerts.run()
Load radar alerts, policy hits, scored records, routes and policy rules.
For each radar alert collect the policy categories of its evidence records and call route_for. Build the alert with emerging_alert. If any evidence record is policy-flagged, set tier to both and merge it with the matching policy alert.
Build policy alerts from non-negated hits with policy_alerts, routed by route_for.
Add the confidence label (Section 11.1), the template explanation text and the uncertainty notes (share of low-confidence records, share of truncated texts, the exposure-proxy statement).
Add the region and the SLA due time (sla_hours from the route).
Mark repeats: same store and issue as a Resolved alert in the last 30 days.
Write alerts.json, then insert into the tracker with INSERT OR IGNORE.
Test: a second run adds no new rows.
22.13 brief.py
Functions: week_bounds(ts) (Monday 00:00 in the configured timezone), build_facts(region, week_start), render(facts), export(region, week_start), run() (all regions and the last N weeks that have data).
build_facts steps:
Take canonical records in the region for the week and for the previous week.
Per issue compute: unique groups now and before, affected stores (at least 2 unique reports or an alert in the week), and share excess against the four weeks before.
Collect the region’s alerts opened in the week plus earlier alerts not yet resolved. Split them into the policy list (all of them) and the emerging list.
Compute the emerging score per issue (largest -log10 p).
Rank with the key in Section 12.2, take five, and for each fill name, severity, owner from routing, trend (12.3), quotes (12.4), rule and action.
Read the due and overdue actions from the tracker.

Problem | Decision | Why
Code-mixed, transliterated, typo-filled text | Char n-gram TF-IDF + multilingual sentence embeddings + a small normalization dictionary. No machine translation. | Pretrained multilingual models know native scripts but are weak on romanized Tamil/Marathi. Char n-grams survive spelling drift. Translation can flip negation and severity.
Few or no labels | Weak supervision (keywords + embedding prototypes vote) plus about 400 records you hand-label | Honest, allowed, and gives you a dev set to tune on instead of touching hidden labels
No exposure denominators | Rate = issue reports ÷ the store’s total unique reports, shrunk toward the global issue share (empirical Bayes) | Small stores borrow strength, big stores do not dominate
Hundreds of store × issue series, so many false alarms | p-value threshold + minimum count + minimum ratio + cooldown + ranking | Controls false alerts per store-week
Duplicates inflate counts | Deduplicate before counting, keep links to originals | Copies must not fake a trend
Duplicates vs corroboration | Count unique groups, but use the number of channels as a confidence booster | Four channels describing one freezer is evidence, not noise
LLM hallucination | Briefs are built from structured facts with templates. An optional local LLM may only reword, then a number-checker verifies it | The spec forbids invented counts or causes
Unknown evaluate.py format | One adapter file, column names in config | Isolates the unknown

Privacy? | Masked text in the UI, no external API calls, raw text access restricted
Does it scale? | The radar costs a few lookups per record and embeddings are batch jobs. Swap SQLite and Parquet for Postgres and a warehouse
